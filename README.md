## Telegram бот подписки

Проект бота на `aiogram 3` для оформления подписки и доступа в закрытый канал.

### Локальный запуск

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python bot.py
```

### Конфигурация

Создайте файл `.env` (не коммитится, см. `.gitignore`):

```env
BOT_TOKEN=...
ADMIN_IDS=6933111964,783321437,6804220900
CHANNEL_ID=-1003721182699
MANAGER_LINK=https://t.me/nastyaprostozhit
BOT_LINK=https://t.me/n_deniseva_bot
```
(BOT_LINK — куда возвращать пользователя после оплаты на bePaid.)

### Метки рекламы (`?start=…`)

- Ссылка: `https://t.me/<ваш_бот>?start=МЕТКА` (латиница, цифры, `_`, `-`, до 64 символов).
- Части UTM-смысла разделяйте **двойным подчёркиванием** `__`: например `vk__march` (источник + кампания) или `viber__broadcast__nov` (+ медиум).
- Бот фиксирует метку **только когда пользователь нажал Старт** по ссылке. Это «first touch»: повторный заход с другой меткой **не перезаписывает** первую.
- При каждой **успешной оплате** (вебхук bePaid + серверное рекуррентное списание) в журнал платежей копируются те же поля метки у пользователя; в `/admin → Метки и кампании` есть сводка, списки и CSV.

Команды для администратора: **`/admin`** (полное меню), **`/stats`** или **`/campaigns`** (сразу раздел меток и оплат по ссылкам). Если этих команд «не было», часто ваш Telegram ID просто отсутствует в **`ADMIN_IDS`** в `.env` на сервере — бот при отказе сообщит ваш ID строкой ниже команды `/admin`.

Опционально в `.env`:

```env
# чтобы строились короткие ссылки вида https://t.me/... если BOT_LINK некороткий
BOT_USERNAME=n_deniseva_bot

# после каждой успешной оплаты отправить короткое сообщение каждому админу из ADMIN_IDS
PAYMENT_ADMIN_NOTIFY=true
```

### Отмена автопродления

Кнопка «Отменить подписку» **снимает карту для автосписаний**, но **не выкидывает** из канала сразу: доступ хранится до конца уже оплаченного периода (как в БД до `subscription_end_date`). После этого работает прежний планировщик (грейс при проблемах с оплатой и т.п.) — **существующие API-подписки и записи пользователей не трогаются**, добавляются только новые столбцы/таблицы при следующем запуске.
